# Meta 工作流：修改后自动沉淀经验

每次用户提完一组修改请求并完成代码/文档改动后，**必须**执行下面这套流程，把可复用经验固化到合适的 docs，避免下次新对话再踩同样的坑。

## 沉淀工作流（每轮必做）

1. **归类**：把本轮反馈按类型归档
   - 命名 / 物理论证 / 写作 / 绘图 / 实验设定 / 工作流 / 其他
2. **判定**：判断哪些是**可复用硬规则**（下次新对话仍会踩坑），哪些是一次性问题（不沉淀）
3. **沉淀**：把可复用规则**追加**到对应的 `.claude/docs/<topic>.md`
   - 找不到合适主题就**新建一个** md 并在 `CLAUDE.md` 加一行索引
4. **行数检查**：完成后 `wc -l CLAUDE.md` 验证 < 200 行
   - 超出就把当前块拆出更多内容到子 md，主文件只保留指针 + 3–5 行硬结论
5. **不沉淀**：一次性 typo、单次拼写、临时数据修正——这些不写进 docs

## 「可复用 vs 一次性」判定标准

**可复用**（必须沉淀）：
- 命名约定（方法名、任务名、术语口径）
- 物理论证立场（哪些写法对、哪些写法错）
- 写作风格（顶会语气 vs 博客语气）
- 绘图规范（调色板、网格、烘焙清单）
- 实验协议（baseline、metrics、organs、views）
- 文件路径与命名前缀
- 工作流（API 调用模板、迭代法）
- 用户明确表达的偏好（「以后别再 ...」「下次默认 ...」）

**一次性**（不沉淀）：
- 当前 PR / 文件 / 段落里的具体改动
- 实验数值的临时修正
- 单次拼写错误
- 已经通过 git 历史可追溯的代码片段

## 子 md 新建命名规范

- 文件路径：`.claude/docs/<topic>.md`
- `<topic>` 用 **kebab-case** 或 snake_case，单词全小写，长度 ≤ 3 词
- 例：`naming.md`、`physics_argument.md`、`figure_design.md`、`meta_workflow.md`
- 主题应是「领域 / 类别」级别，不要太细（如 `intro_paragraph_2.md` 过细）也不要太泛（如 `all_rules.md` 过泛）

## 与现有规则冲突的反馈如何处理

- **用户最新指令永远优先**
- 沉淀新规则时，**同步修改**旧规则——而不是叠加两条互相冲突的规则
- 若必要，在新规则旁加 `<!-- 取代旧 XXX 规则 -->` 注释（仅写在 docs 内部，不进 CLAUDE.md 索引）
- 不要让 docs 出现「A 说 X，B 说非 X」的矛盾，否则下次对话仍会犯错

## 行数硬门禁

- `wc -l CLAUDE.md` 必须 < 200
- 超 200 视为**本轮任务未完成**，必须继续拆分到子 md
- 主 CLAUDE.md 每个主题块预算：**≤ 10 行**（含标题、3–5 行硬结论、指针、空行）
- 如果某主题硬结论超过 5 行，立刻拆出更多内容到子 md，主文件只保留最高频的部分

## 自检 checklist（每轮收尾）

- [ ] 本轮反馈已归类
- [ ] 可复用规则已写入对应 `.claude/docs/<topic>.md`
- [ ] 新建 md 已在 CLAUDE.md 加一行索引
- [ ] `wc -l CLAUDE.md` < 200
- [ ] 旧规则若被取代，已同步修改而非并存
